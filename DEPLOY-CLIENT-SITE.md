# Клиентский сайт devBIM: деплой north-waterfront

Назначение: отдельный веб-деплой `dsh web` для передачи клиенту («Северный берег»),
изолированный от внутреннего `devbim.dev-bim.com`: свой порт (3081), свой
`DSH_HOME` (сессии, креды, настройки), свой пароль входа и урезанный UI —
клиенту доступны только чат и окно «Чертежи». Внутренний сайт продолжает
работать на 3080 без изменений.

## Состав

Файлы в репозитории (ветка `webUI`):

- `packages/bundle/web-app/client-north-waterfront.patch.yml` — оверлей
  клиентского сайта: NW-бренд (пакет `ui-brand-north-waterfront`: бейдж NW и
  «north-waterfront» в сайдбаре и герое), парольный гейт `devbim-auth` с NW-копией
  входа (`entryTitle` «NW — вход», вордмарк NW) и титулом вкладки
  (`indexTitle` «NW — Северный берег», переписывается на каждый запрос — сборка
  отдаёт общий дефолт), модели (openrouter, ключ из клиентских кредов, список
  `NW_MODELS` вместо полного каталога), `trustedHosts` домена, отключения
  командных поверхностей UI, пресет агента
  «только чертежи» и режимы доступа, сжатые до одного `workspace-write`
  с закреплённым дефолтом (клиент работает в своей папке рабочей области,
  переключить режим нельзя);
- `dsh-web-north-waterfront.cmd` — лаунчер: порт 3081, `DSH_HOME=%USERPROFILE%\.dsh-north-waterfront`,
  env из `.env.north-waterfront`, туннель `config-north-waterfront`;
- `nw-models.cmd` — батник списка моделей: пишет `NW_MODELS` в env, показывает
  текущий список, сбрасывает на дефолт оверлея и предлагает перезапуск;
- `.env.north-waterfront` — секреты сайта (в `.gitignore`): пароль входа,
  `DRAWING5_API_KEY`, `DRAWING5_SERVER_URL`, при необходимости `NW_MODELS`
  (список доступных в выборе моделей).

Машинные артефакты:

- `%USERPROFILE%\.dsh-north-waterfront` — home клиента; профиль `web` с
  плагином `dsh-plugin-drawing5`; `.credentials.yaml` — копия внутренней с
  удалённой записью `client-connection/browser-session` (секрет(cookie) сайта
  свой, создаётся при первом старте);
- `%USERPROFILE%\.cloudflared\config-north-waterfront.yml` — туннель
  `north-waterfront` → `http://127.0.0.1:3081` (service строго `127.0.0.1`,
  не `localhost`).

## Развертывание нового клиента

1. Лицензия drawing5: `python -X utf8 -m cloud.issue_license --company "<клиент>"`
   из репозитория drawing5; токен — в `.env.<клиент>` как `DRAWING5_API_KEY`.
2. Домен и туннель: `cloudflared tunnel create <имя>`,
   `cloudflared tunnel route dns <имя> <домен>`,
   `config-<имя>.yml` по образцу `config-devbim.yml` (ingress: домен →
   `http://127.0.0.1:<порт>`).
3. Оверлей: скопировать `client-north-waterfront.patch.yml`, заменить домен в
   `connection`; список отключений и пресет агента — по образцу.
4. Лаунчер: скопировать `dsh-web-north-waterfront.cmd`, заменить `PORT`,
   `DSHHOME`, `ENV_FILE`, имя туннеля и аргумент `--port`.
5. Home: скопировать структуру `%USERPROFILE%\.dsh-north-waterfront`
   (профиль `web` + плагин из `drawing5/plugin/dsh-plugin-drawing5/dist`,
   креды без `client-connection/browser-session`).

## Запуск и проверка

```sh
dsh-web-north-waterfront.cmd start    # сервер 3081 + туннель
dsh-web-north-waterfront.cmd stop
dsh-web-north-waterfront.cmd restart
```

Чек-лист: `http://127.0.0.1:3081/` даёт 303 → `/devbim/login`; неверный
пароль — 401; верный — вход. Страница входа: титул «NW — вход», вордмарк NW.
После входа: бейдж NW и «north-waterfront» в сайдбаре, титул вкладки
«NW — Северный берег»; devBIM нигде не виден (внутренний сайт на 3080
продолжает показывать devBIM). В UI: чат отвечает, «Чертежи» показывает дерево
клиента; выбор модели есть, но показывает только `NW_MODELS` (настройки,
Plugins, терминал и файлы отсутствуют); список сессий пуст (изоляция от
внутреннего сайта). Чип режима агента доступен:
штатный «Стандартный» и пункт «Свой агент» (конструктор кастомных агентов,
см. ниже); селектор режима возле «+» и команда Permission внутри «+»
показывают единственный режим «Запись в рабочей области» (Workspace Write).
Публично: тот же чек-лист через домен туннеля.

## Выбор модели

Пикер модели (`ui-model-selection`, `/model` и кресло модели в композере)
включён, но каталог OpenRouter заменён списком `NW_MODELS` из
`.env.north-waterfront` — клиент видит и может выбрать только эти модели.
Без переменной действует список из оверлея; чтобы переопределить его,
добавьте в `.env.north-waterfront` строку вида:

```ini
NW_MODELS=deepseek/deepseek-v4.1-flash,deepseek/deepseek-v4-pro,deepseek/deepseek-v4-flash
```

Список можно менять батником `nw-models.cmd` (рядом с лаунчером):

```sh
nw-models.cmd "deepseek/deepseek-v4.1-flash,deepseek/deepseek-v4-pro"
nw-models.cmd show     # показать текущий список
nw-models.cmd reset    # удалить NW_MODELS, вернуть дефолт оверлея
```

Правила:

- первая модель списка — дефолт для новых сессий; остальные — варианты выбора;
- id — из каталога OpenRouter, встроенного в pi-ai; модель вне каталога
  даст диагностику при запросе;
- список читается при старте: после правки `.env.north-waterfront` нужен
  перезапуск (`dsh-web-north-waterfront.cmd restart`);
- `ui-settings-models` остаётся отключённым, поэтому клиент не может добавить
  провайдера или расширить список через настройки; нативные DeepSeek-адаптеры
  в оверлее отключены, чтобы в пикере не появились их несокращённые каталоги;
- выбор проверяется на Host (`session.selectModel` → `modelAvailable`), поэтому
  модель вне списка отклоняется с `session/model-unavailable`, даже если её
  попытаться выбрать в обход UI.

Уже созданные сессии сохраняют модель, с которой начаты; новый список
действует на новые сессии и на явный выбор в существующей.

## Свои агенты (кастомные пресеты)

Пользователи сайта создают своих агентов через пункт «Свой агент» в чипе
выбора режима (над полем ввода на пустой сессии): имя, описание, инструкция
и выбор инструментов из whitelist. Записи хранятся как данные в
`%USERPROFILE%\.dsh-north-waterfront\storages\` (домен `custom_agent_presets`,
json — по одному файлу на запись) и монтируются в реестр пресетов как
`custom/<slug>`; выбор и смена — штатным чипом до первого сообщения сессии.

Границы безопасности: пользовательский ввод превращается только в значения
типизированной конфигурации (никакого YAML/кода от пользователя Loader не
получает); каждому агенту подставляется префикс-персона сайта; фиксированные
базовые строки (инструкции, время, компактация, доставка файлов `present`)
копируются оверлеем из `preset-standard`; инструменты — только чекбоксы из
`allowedTools` оверлея (`Вопросы пользователю`, `Задачи`, `Чертежи
(drawing5)`, `Сметы (БелЕНиР)`). Отмеченный чекбокс монтирует строку в
агента, снятый — жёстко блокирует: строки MCP drawing5/smeta отключены на
host-plane и монтируются только внутри выбранного агента. Расширять
whitelist — только после ревью песочницы добавляемых строк. Лимиты (длина
инструкции 16384 символов, до 50 агентов на сайт) и список — в конфиге
`agent-preset-custom` того же оверлея. Список общий на весь сайт (вход по
одному паролю, identity нет): правка и удаление доступны всем вошедшим.
Битая запись (нарушение схемы в файле) при старте уходит в бэкап с записью
в лог и в ростер не попадает.

## Ограничения

Ограничения — на уровне UI: RPC-поверхность вошедшего браузера не ограничена
по принципалу (remoteAccess считает соединение owner); пароль — единственный
барьер. Для выдачи наружу держите пароль одноразовым и меняйте при передаче.
Отключения UI и набор инструментов агента — список строк в оверлее, правится
за одну минуту.
