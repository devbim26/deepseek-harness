# @deepseek-ai/dsh-agent-orchestrator

[English](README.md) | 中文

## 概述

Запускает несколько специализированных субагентов против одной цели, позволяет оценщику судить их отчёты и отправляет точечные уточнения в те же дочерние Session вместо повторного старта. Движок сохраняет историю и идентичность каждого работника между раундами, отказывает в вопросах человеку и превращает каждый недостающий факт в явный пробел. Завершённые прогоны несут статус `complete`, `partial` или `budget-limited`; проваленные и отменённые прогоны никогда не дают отчёт, который можно принять за завершённый. Сервис владеет бюджетом раундов, очисткой детей и созданным PDF.

<a id="use-this-package"></a>
## 使用本包

Монтируйте плагин там, где кастомному агенту нужна многоспециалистская проверка, затем вызовите `ctx.agentOrchestrator.start()` с точным живым корневым Agent. Прогон foreground: он разрешается, когда все дети очищены.

### 何时选择

Выбирайте этот движок, когда одна цель требует нескольких независимых специализированных проходов и оценщика, способного вернуть уточняющие вопросы тем же работникам. Выбирайте обёртку для модели [dsh-tool-agent-orchestrator](../tool-agent-orchestrator/README.zh.md), когда сохранённая запись кастомного агента должна открыть весь поток одним инструментом. Используйте обычного субагента, когда один делегат может ответить напрямую.

### 最小配置

```yaml
plugins:
  - id: agent-orchestrator
    plugin: '@deepseek-ai/dsh-agent-orchestrator'
    config:
      provider: spawn
      maxHandoffChars: 65536
      maxSettledRuns: 32
      reportDirectory: reports
```

| Поле | По умолчанию | Значение |
|---|---|---|
| `provider` | `spawn` | Провайдер субагентов для работников и оценщика. |
| `maxHandoffChars` | `65536` | Максимальный размер сериализованного набора работников, передаваемого оценщику. |
| `maxSettledRuns` | `32` | Снимки завершённых прогонов, которые сервис хранит в процессе. |
| `reportDirectory` | `reports` | Папка относительно сессии, принимающая созданные PDF-файлы. |

Сгенерированный [каталог конфигурации](../../../docs/config-catalog.zh.md#deepseek-aidsh-agent-orchestrator) — исчерпывающий источник всех принимаемых полей. Лимиты раундов и параллелизма — поля запроса, а не конфигурации плагина: `start()` принимает `maxIterations` (раунды, включая первый), `maxParallel` (одновременно активные работники) и необязательные заголовок и детали отчёта.

<a id="understand-the-implementation"></a>
## 理解实现

Движок не отправляет собственных запросов к модели: каждое видимое модели слово приходит из трёх промптов в `src/prompts.ts`, каждый доставляется как начальная задача ребёнка.

<details>
<summary>实现内部 — 点击展开</summary>

Первый раунд начинает по одной дочерней Session на задание. Раунд уточнений продолжает ту же дочернюю Session через `resumeActivation()`, поэтому делегат сохраняет историю и идентичность. Работники выполняются параллельно до `maxParallel`; оценщик выполняется один раз за раунд. Движок владеет бюджетом раундов: `maxIterations` считает первый раунд, поэтому 3 — это один начальный раунд и два раунда уточнений. Каждому ребёнку запрещён `ask_user_question` до его первого запроса к модели. Прогоном может владеть только точный живой корневой Agent; вложенная оркестрация отклоняется с `ORCHESTRATION_NESTED`.

| Статус | Значение | Отчёт |
|---|---|---|
| `complete` | Оценщик принял собранные отчёты. | Записан |
| `partial` | Оценщик принял работу с явными пробелами. | Записан, помечен неполным |
| `budget-limited` | Последний оценщик всё ещё требовал уточнений. | Записан, помечен неполным |
| `failed` | Оценщик не дал пригодного решения, или шаг жизненного цикла сбойнул. | Нет |
| `cancelled` | Вызывающая сторона отменила прогон. | Нет |

Карта источников: `src/index.ts` определяет Service и валидированный `Config`; `src/run.ts` владеет контроллером раундов и жизненным циклом детей; `src/prompts.ts` владеет тремя видимыми модели промптами; `src/report.ts` пишет PDF; `src/schemas.ts` разбирает решения оценщика.

`src/report.ts` превращает завершённый результат в таблицу параметров и текстовые разделы, которые рендерит [dsh-tool-pdf](../../document/tool-pdf/README.zh.md). Строка отчёта, начинающая pipe-таблицу, печатается как эта таблица; каждая прочая строка доказательства, допущения, пробела или ошибки печатается одним пунктом списка. Промпты просят каждую модель помечать ключевые факты и цифры через `==...==`, и PDF печатает эту пометку жёлтой полосой. Прогон хранит пометки только для PDF: `run.result` и каждый опубликованный снимок несут те же тексты без них, потому что вызывающая модель, поверхность Remote и журналы прогонов читают пометку как буквальный текст. Строка отчёта, которая называет кроп Markdown-ссылкой на изображение в постоянном хранилище вложений, печатается как это изображение: текст ссылки становится подписью, а пиксели берутся из собственного результата инструмента Session.

</details>

<a id="model-experience"></a>
## 模型体验

### 工作者任务

#### 模型看到什么

Работник получает промпт задания, затем заявление об автономии, инструкцию по отчёту и формат текста отчёта. Заявление об автономии читается как `Do not ask a human questions or wait for confirmation. Record missing facts as explicit assumptions or gaps and continue with the available evidence.` Инструкция и формат отчёта читаются как `Return a structured report with summary, evidence, assumptions, and gaps. Every text field of the report is printed in a PDF that renders a small Markdown subset: write it as prose, "- " list items, or a pipe table with a header row and a --- separator row, and wrap the key facts, figures, and conclusions in ==...== so they print on a yellow band. Mark sparingly and never a whole sentence.`

#### Token 影响

Одно предложение об автономии и одна инструкция по отчёту с форматом текста отчёта на работника, дописанные к промпту задания.

#### KV Cache 效应

Блок пишется один раз в начальную задачу ребёнка, которая становится стабильным префиксом каждого запроса в этой дочерней Session. Раунды уточнений переиспользуют этот префикс.

### 工作者追问

#### 模型看到什么

Продолжение в той же Session работника читает `Follow-up for your previous work: <question>`, необязательно `New circumstances: <circumstances>`, то же заявление об автономии и `Return a new structured report that replaces your previous summary and accounts for this follow-up.`

#### Token 影响

Один заголовок уточнения, вопрос и необязательные обстоятельства, а также инструкции об автономии и замене на каждый раунд уточнений.

#### KV Cache 效应

Только дописывание: уточнение дописывается после сохранённой истории работника, поэтому существующий префикс остаётся переиспользуемым.

### 评估者决策

#### 模型看到什么

Оценщик получает `Original objective: <objective>`, необязательно `Initial circumstances: <circumstances>`, `Current worker reports: <JSON>`, заявление об автономии и контракт решения. Контракт открывается словами `Evaluate completeness. Answer with exactly one JSON object using only these fields and no others:`, называет по одной строке на вид решения с его точными JSON-полями, закрывается словами `Fields of the other kinds must be omitted, not left empty or null. Do not request more work than the remaining round budget can perform.` и завершается тем же форматом текста отчёта, который получает работник.

#### Token 影响

Доминирующая стоимость — сериализованный набор работников, ограниченный `maxHandoffChars`; фиксированная обвязка — строка цели, необязательная строка обстоятельств, заявление об автономии и контракт решения с форматом текста отчёта. Превышение передачи рушится с `ORCHESTRATION_HANDOFF_LIMIT` до старта любого запроса к оценщику.

#### KV Cache 效应

Session оценщика переиспользуется между раундами, поэтому передача каждого раунда дописывается к сохранённой истории оценщика, а не заменяет её.

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- Прогоны foreground и process-local: перезапуск процесса их не возобновляет, а владеющий адаптер сообщает о неизвестном прогоне как о недоступном.
- Отчёты содержат текст, таблицы и кропы, произведённые Session; собственные изображения вложений ребёнка в родительскую Session не переносятся.
- Текст отчёта принимает только подмножество Markdown из [dsh-tool-pdf](../../document/tool-pdf/README.zh.md); курсив, ссылки и вложенные inline-пометки печатаются как написаны, кроме ссылки, которая называет произведённый Session кроп: она печатается как это изображение.
- Прогоном может владеть только точный живой корневой Agent; вложенная оркестрация отклоняется.
- Движок хранит не более `maxSettledRuns` снимков завершённых прогонов на scoped-сервис.
