# Дизайн: загрузка и анализ документов в клиентском проде NW

Дата: 2026-11-16. Статус: утверждён пользователем.

## Контекст и цель

Клиентский прод `north-waterfront.dev-bim.com` запускается как `dsh web --port 3081 --patch packages/bundle/web-app/client-north-waterfront.patch.yml`. Оверлей оставляет пользователю чат, выбор агента и окно «Чертежи»; настройки, файловые панели, терминал и офисные инструменты скрыты.

Сейчас клиент не может приложить документ к сообщению: строка `ui-attachment` в оверлее отключена, а пресет `standard` не содержит ни файловых инструментов, ни Office-стека. Причина отключения зафиксирована в комментарии оверлея: без fs-инструментов вложения бесполезны — модель получает только путь к сохранённой копии, но не может её прочитать.

Модели сайта (`NW_MODELS`, по умолчанию `deepseek/deepseek-v4.1-flash` и родственные) по каталогу OpenRouter принимают только текст (`input_modalities: ["text"]`). Поэтому анализ не может опираться на рендер страниц в изображения: нужен текстовый слой документов.

Цель — дать клиенту прикладывать документы к сообщению и получать ответы по их содержимому, не выдавая агенту shell, файловые инструменты и Office-скиллы.

Решения брейншторма:

- Документы добавляются вложением в чат; отдельного окна «Документы» и сохранения в рабочую папку в v1 нет.
- Форматы: PDF, DOCX, DOC, XLSX, XLS, TXT, CSV.
- Сканы PDF без текстового слоя не распознаются: агент явно сообщает, что текста нет, и просит текстовую версию. OCR и vision-модели не входят в объём.
- Выбран вариант A: новый model-facing инструмент с извлечением текста на Host; готовый Office-стек (вариант B) отклонён из-за отсутствия извлечения текста из PDF и широкого fs-доступа, предварительное извлечение при загрузке (вариант C) — из-за раздувания контекста и отсутствия постраничности.

## Архитектура

### 1. Хост: `@deepseek-ai/dsh-tool-document`

Новый пакет `packages/document/tool-document/` в группе `document`. Один model-facing инструмент `document_read`; сервис не выделяется, потому что других потребителей у извлечения текста нет.

Инструмент принимает абсолютный путь из строки-хэндла вложения, которую `FileBlock` уже проецирует в промпт, и параметры выбора окна:

| Параметр | Тип | Смысл |
|---|---|---|
| `path` | string, обязательный | Абсолютный путь сохранённой копии вложения из хэндла `File "<name>" ... saved at "<path>"` |
| `page` | integer ≥ 1, опциональный | Страница PDF; по умолчанию 1 |
| `sheet` | string, опциональный | Лист книги; по умолчанию первый |
| `row` | integer ≥ 0, опциональный | Номер первой строки данных выбранного листа (0-based) |
| `offset` | integer ≥ 0, опциональный | Смещение в символах внутри выбранной страницы или текста документа; по умолчанию 0 |
| `limit` | integer ≥ 1, опциональный | Максимум символов в ответе; урезается конфигом |

Формат определяется по расширению сохранённого файла: путь в хранилище заканчивается исходным именем (`$DSH_HOME/attachments/v1/files/<sha2>/<sha256>/<name>`), поэтому расширение доступно без отдельного запроса.

Извлечение по форматам:

| Формат | Механизм | Замечания |
|---|---|---|
| PDF | `pdfjs-dist` (ESM), текстовый слой выбранной страницы | `pageCount` из документа; страница без текста даёт `no-text-layer`; скан целиком — тот же код |
| DOCX | `fflate` (unzip) + разбор `word/document.xml` | Абзацы, таблицы, `<w:tab/>`, `<w:br/>`; колонтитулы и сноски в v1 не извлекаются |
| XLSX, XLS | `xlsx` (SheetJS, ESM-сборка) | Список листов; выбранный лист сериализуется в TSV по used range; ячейка — форматированное значение, а при наличии формулы — `значение (=формула)` |
| DOC | `officeKit.convertTo('txt')`, затем чтение результата | Требует смонтированный `office-kit`; при отсутствии — `converter-unavailable` |
| TXT, CSV | чтение байтов и декодирование | UTF-8 с BOM и без; при ошибке декодирования — windows-1251 |

Извлечение выполняется в процессе Host. Внешние конвертеры и shell не используются, кроме LibreOffice Kit для `.doc`.

### 2. Ограничение доступа к путям

Инструмент читает только общие файлы-вложения текущей сессии. Перед извлечением он собирает `FileAttachmentRef` из поверхности сообщений сессии, переводит каждый в путь через `ctx.attachments.fileHostPath(ref)` и сравнивает с запрошенным абсолютным путём после нормализации. Несовпадение — ошибка `not-an-attachment`.

Это исключает чтение произвольных файлов хоста клиентским сайтом: агент не получает fs-инструментов, а `document_read` не принимает пути вне вложений сессии. Изображения-вложения не подходят: их тип — `ImageAttachmentRef`, не `FileAttachmentRef`.

### 3. Выдача и продолжение

Ответ начинается со строки метаданных: имя, формат и размер; для PDF — число страниц и объём текста выбранной страницы; для книг — список листов, выбранный лист и его used range; для остальных форматов — полный объём извлечённого текста. Затем идёт окно текста не длиннее `maxChars`.

- PDF: метка `--- page <n> ---`, текст выбранной страницы; при наличии следующих страниц ответ подсказывает `document_read` с `page`.
- DOCX, DOC, TXT, CSV: весь документ извлекается один раз, окно режется по `offset`/`limit`; при остатке ответ даёт `nextOffset`.
- XLSX, XLS: заголовок листа и диапазон, строки TSV не длиннее `maxRows`; продолжение — `row` со следующим номером строки.

Текст документа — данные, а не инструкции: инструмент не интерпретирует его и не исполняет.

### 4. Конфигурация

Все эксплуатационно-зависимые значения — поля `Config` пакета:

| Поле | Значение по умолчанию | Смысл |
|---|---|---|
| `maxInputBytes` | 50 МиБ | Верхняя граница входного файла; больше — `too-large` |
| `maxChars` | 20 000 | Окно текста в одном ответе |
| `maxRows` | 500 | Строк листа в одном ответе |
| `timeoutMs` | 30 000 | Дедлайн извлечения; по истечении — `timeout` |

Значения читаются из строки пакета в оверлее; в коде нет `DEFAULT_*`-переопределений помимо схемы.

### 5. Ошибки

`HarnessError` с кодами: `unsupported-format`, `too-large`, `unreadable`, `no-text-layer`, `not-an-attachment`, `converter-unavailable`, `timeout`.

Сообщения model-facing на английском, с именем файла и действием: пересохранить в поддерживаемый формат, запросить текстовую версию скана, повторить позже при занятом конвертере. Ошибки не раскрывают содержимое других файлов и пути вне вложения.

### 6. Оверлей `client-north-waterfront.patch.yml`

- Убрать строку `- id: ui-attachment / disabled: true` и заменить комментарий: вложения теперь используются инструментом документов. Пункт «Файл» в меню «+», перетаскивание и карточки вложений становятся доступны без дополнительных клиентских правок.
- Добавить `tool-document` в `preset-standard.plugins` рядом с `tool-todo`.
- Добавить ключ `documents` в `agent-preset-custom.allowedTools` с русскими `label`/`description`, чтобы кастомный агент мог включить инструмент чекбоксом.
- Shell, fs, Office-скиллы и остальные панели остаются отключёнными. `office-kit` уже смонтирован на host-плоскости базового web-бандла и не отключается оверлеем; он нужен только для `.doc`.

### 7. Манифест бандла

`packages/bundle/web-app/package.json` получает зависимость `@deepseek-ai/dsh-tool-document` (`workspace:*`), чтобы имя строки разрешалось `verify-cordis-config`. `pnpm install` связывает workspace-пакет.

## Потоки

### Загрузка и анализ

1. Клиент нажимает «+» → «Файл» (или перетаскивает файл) и прикладывает PDF/DOCX/XLSX к сообщению.
2. `file-upload` и `attachment-local` сохраняют байты под `DSH_HOME`; сообщение получает `FileBlock`, а запрос — детерминированную строку с путём.
3. Модель вызывает `document_read` с этим путём и при необходимости с `page`/`sheet`.
4. Инструмент проверяет, что путь принадлежит вложению текущей сессии, извлекает текст и возвращает метаданные и окно.
5. Модель отвечает по содержимому; при больших документах продолжает с `offset` или следующей страницей.

### Особые случаи

- Скан PDF: `no-text-layer`, модель сообщает об отсутствии текстового слоя и предлагает прислать текстовую версию.
- `.doc` при недоступном Kit: `converter-unavailable`, без подмены системным `soffice`.
- Файл больше `maxInputBytes`: `too-large` до чтения.
- Неподдерживаемое расширение: `unsupported-format`; модель перечисляет поддерживаемые форматы.
- Несколько документов: каждый читается своим вызовом; сравнение — обычная работа модели по извлечённым текстам.

## Безопасность

- Агент не получает shell, fs, Office-скиллы и доступ к произвольным путям; единственный вход — вложения текущей сессии.
- Разбор недоверенных документов идёт в процессе Host библиотеками без песочницы; это тот же класс риска, что нативный движок `office-kit` в `tool-office`. Размер входа, число страниц/строк и дедлайн ограничены; парсеры получают только байты вложения.
- Текст документа не становится инструкциями: результат — данные в tool-сообщении.
- Ошибки не содержат чужих путей и содержимого.

## Тестирование и проверки

- Юнит-тесты пакета: каждый экстрактор на маленьких фикстурах; guard путей (вложение принято, произвольный путь отклонён); лимиты и окна; все коды ошибок; `.doc` с подставным `officeKit` и без него.
- 100% покрытие файлов `src` нового пакета (`pnpm run test:coverage` для пакета).
- Перегенерация `docs/tool-catalog.md` и его китайской пары; README пакета и группы `packages/document` на en/zh с i18n-парой.
- `pnpm run build:artifacts`, затем `pnpm run build:check`; focused-тесты пакета; `pnpm run doc-sync`; `pnpm run verify-cordis-config`.
- Снапшоты сессий не меняются: инструмент не монтируется в поставляемые профили, только в NW-оверлей.

## Деплой в прод NW

1. `pnpm install` — связать новый workspace-пакет.
2. `restart-north-waterfront.cmd` — перезапуск `dsh web` на :3081 из исходников.
3. Смоук в браузере: вход по паролю, «+» → «Файл», вложение PDF, DOCX и XLSX, вопрос по содержимому каждого; скан PDF даёт честный отказ; список инструментов агента по-прежнему без fs/shell.
4. Откат — вернуть строки оверлея и перезапустить лаунчер.

## Вне объёма

- OCR сканов и vision-модели.
- Извлечение изображений и вложенных объектов из документов.
- PPT/PPTX, ODT/ODS и прочие форматы.
- Загрузка документов в рабочую папку, файловая панель, предпросмотр в сайдбаре.
- Разделение документов по пользователям сайта.
- Извлечение колонтитулов, сносок, комментариев, текстовых полей и надписей DOCX.

## Риски

- `pdfjs-dist` в Node без DOM: для текстового слоя нужен legacy-вход и отключённый eval; проверить спайком до остальной реализации.
- SheetJS подключается тем же CDN-тарболом `0.20.3`, что и клиентский предпросмотр; если `pnpm install` не сможет использовать store, потребуется сетевой доступ.
- `.doc` зависит от нативного LibreOffice Kit под win32-x64; в текущем workspace пакет установлен.
- DOCX-разбор XML ручной: покрыть фикстурами с таблицами, пробелами `xml:space="preserve"` и спецсимволами.
