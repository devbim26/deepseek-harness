# Дизайн: пользовательские пресеты агентов для клиентского прода

Дата: 2026-11-15. Статус: на утверждении пользователем.

## Контекст и цель

Клиентский прод `north-waterfront.dev-bim.com` запускается как `dsh web --patch packages/bundle/web-app/client-north-waterfront.patch.yml`. Этот оверлей сознательно скрывает все поверхности настройки — включая `ui-agent-preset` (строка 92): выбор «режимов» агента в клиентском проде недоступен.

Причина скрытия существенна: пресет агента — это список дочерних плагинов Cordis, и YAML пресета исполняет произвольный код на хосте (`packages/preset/agent-preset-registry/README.md`, «Presets are not security sandboxes»). Штатный путь «создать своего агента» (Creator-режим `cordis`: агент авторит бандл, установка через plugin manager) для публичного клиента означает RCE на сервере, поэтому он в оверлей не возвращается.

Цель — дать пользователям клиентского прода безопасно создавать своих агентов и выбирать их из списка кастомных. Безопасность = пользовательский ввод никогда не становится YAML/кодом: он хранится как данные и превращается в плагины только через закрытую схему.

Решения брейншторма:

- Вариант A — «пресеты-как-данные»: новый ограниченный конструктор; произвольные пресеты (вариант C, Creator) отклонены как небезопасные; вариант B («только вернуть переключатель») остаётся доступным деградационным шагом — он делается одной правкой оверлея и совместим с этим дизайном.
- Пользователь настраивает: имя, описание, инструкцию (персону) и выбор инструментов из whitelist, задаваемого оверлеем деплоя.
- Хранение — длительные данные в `DSH_HOME` через `storage-domain` (форма `dsh-storage-domain`, бэкенд `json`), по одной записи на файл.
- Список кастомных агентов общий на сайт (вход по одному паролю, identity нет); разделение по пользователям — отдельная задача, не входит в объём.
- Whitelist первого шага: `tool-ask-user`, `tool-todo`; инструменты чертежей (drawing5) — host-plane и доступны без пресета, в whitelist не входят.

## Архитектура: компоненты

### 1. Хост: `@deepseek-ai/dsh-agent-preset-custom`

`packages/preset/agent-preset-custom/`. Полный seam по конвенции репозитория:

- Service Definition — сервис `customAgentPresets` на контексте; Remote-методы `list / create / update / delete` (typert, по образцу `agentPresets` в `packages/preset/agent-preset-registry`).
- Service Provider — тот же пакет: владеет хранилищем записей (storage-domain KV-домен, бэкенд `json`) и регистрирует синтезированные определения в существующем реестре.
- Consumer — клиентский плагин (компонент 2) и оверлей деплоя (компонент 3).

Запись кастомного агента — закрытая схема, валидируется на remote-границе:

| Поле | Ограничение |
|---|---|
| `id` | slug `[a-z0-9][a-z0-9-]*`, в ростер попадает как `custom/<slug>` — префикс исключает коллизии со штатными id |
| `name` | непустое, ≤ 64 символов |
| `description` | ≤ 200 символов |
| `instructions` | ≤ 16 384 символов |
| `tools` | ключи из `allowedTools` конфига (каждый опционален) |
| `version` | назначается сервисом при каждой записи — оптимистическая блокировка обновлений |

Whitelist конфигурируется картой `allowedTools`: ключ записи → строка плагина `{ name, config? }`, которую сервис подставляет в синтез как есть (например `askUser: { name: '@deepseek-ai/dsh-tool-ask-user' }`). Запись агента хранит только ключи — имена плагинов приходят из оверлея деплоя, из кода их не подставляем.

Все числовые лимиты, префикс id, `allowedTools` и `basePlugins` — конфигурируемые поля сервис-строки (правило «no hardcoded tunables»: менять из `cordis.yml`/оверея, дефолты в схеме), кроме литерала `custom/` — это протокол адресации ростера.

Жизненный цикл определения:

- `create` — валидация → запись в storage-domain → синтез `{ name, plugins: [persona(prefix = instructionsPrefix + instructions), …basePlugins, …строки whitelist по выбранным ключам] }` → `ctx.agentPresets.register()` через `ctx.effect()` (регистрации — эффекты; disposer сохраняется).
- `basePlugins` — конфиг-список фиксированных строк пресета без персоны: `agent-instructions`, `time-context`, группа compaction. Оверлей копирует их из сохранённого им же `preset-standard` (оба списка живут рядом в одном файле — дрейф виден при правке). Без этого кастомный агент терял бы компактацию и контекст — поэтому шаблон, а не только whitelist, принадлежит деплою.
- `instructionsPrefix` — конфиг-строка сайта («You are the drawings assistant of the north-waterfront client site…»), сервис склеивает её с инструкцией пользователя; персона сайта сохраняется у любого кастомного агента.
- `update` — отрегистрация старой ревизии (disposer) + регистрация новой; реестр ретирит предыдущую ревизию, **уже запущенные сессии сохраняют свою композицию** (задокументированное свойство реестра).
- `delete` — отрегистрация; строка уходит из ростера; записи, адресующие её в логах сессий, остаются валидными историческими ссылками (реестр держит ревизию, пока есть ссылки).
- Бут — перечитка домена, регистрация всех записей до подъёма веб-сервера; восстановление после рестарта сессии разрешает пресет по id из лога, как для штатных пресетов.

Model-visible ⟺ logged: инструкция попадает в модель через `persona`-плагин пресета; выбор пресета фиксируется в логе сессии штатным событием `agent-preset/selected` (сессия-проекция `agentPreset` без изменений), а само определение восстанавливается из длительного хранилища по id — та же схема реконструкции, что у установленных бандлов и выбранной модели.

### 2. Клиент: `@deepseek-ai/dsh-client-ui-custom-agents`

`packages/client/ui-custom-agents/`. Расширение UI по существующему паттерну `dsh.client` + слоты:

- Точка входа — кнопка «＋ Свой агент» в попапе чипа выбора агента над полем ввода. Для этого `ui-agent-preset` получает новый слот попапа (например `agentPreset.picker.actions`): чип остаётся владельцем ростера, кастом-пакет только заполняет слот. Внутренний деплой получает ту же кнопку бесплатно.
- Форма создания/редактирования: имя, описание, инструкция (textarea с счётчиком), чекбоксы инструментов из whitelist (список читается из remote-конфига сервиса — форма показывает только разрешённое).
- Список «Кастомные агенты» с правкой и удалением; удаление — с подтверждением.
- Ростер чипа уже показывает кастомные пресеты автоматически: они приходят через общий `remote.agentPresets.list()` и группируются как «кастомные» (`isBuiltInPreset` различает штатные id).
- Копирайт — через типизированные словари и `t` (правило locale-owned UI copy); язык интерфейса клиентского прода — русский.

### 3. Оверлей `client-north-waterfront.patch.yml`

- Убрать `disabled` у `ui-agent-preset` — вернутся чип и лейбл режима в шапке сессии. Побочных появлений нет: пункт «пусть агент создаст плагин» не рендерится без пресета `cordis` в ростере, PTC/Minimal/Creator скрыты гейтом Coding Tools (выключен), секция настроек недостижима (настройки скрыты).
- Вставить строки `agent-preset-custom` (хост) и `ui-custom-agents` (клиент) с конфигом whitelist и лимитов.
- Обновить шапку-комментарий оверлея (перечень скрытых поверхностей теперь неполный без оговорки про кастом-агентов).

## Потоки

### Создание агента

1. Пользователь открывает чип на пустой сессии → «＋ Свой агент» → форма.
2. Сабмит: remote `create` → валидация схемы на границе → запись на диск → `agentPresets.register()`.
3. Ростер чипа перечитывается после ответа `create` (клиент вызывает штатный refresh чипа/секции; пуш-канала не нужно — форму и чип видит один пользователь в одном окне) → пользователь выбирает агента в чипе → штатный `select` до первого хода, событие `agent-preset/selected` в логе.

### Редактирование и удаление

1. Форма открывается на существующей записи; `update` пересобирает определение новой ревизией.
2. Сессии, уже работающие на старой ревизии, её сохраняют; новые сессии получают обновлённую.
3. `delete` убирает строку из ростера; попытка выбрать несуществующий пресет возвращает штатную ошибку `agent-preset/not-found`.

### Рестарт

- Записи живут в `DSH_HOME` (json-файлы), бут перерегистрирует их; восстановленная сессия с `custom/<id>` в логе монтирует текущую ревизию этого id; если запись удалена — штатный отказ восстановления с внятной причиной (поведение реестра для отсутствующих определений).

## Обработка ошибок

Принцип «misconfiguration fails loud»:

- Неизвестный tool id, дубликат slug или имени, превышение лимитов — отклонение remote-вызова с кодированной ошибкой (`custom-agent-presets/invalid|not-found|limit`), форма показывает причину.
- Битая запись на диске (нарушение схемы) не роняет бут: запись переводится в карантин, сервис отдаёт её в `list` с диагностикой, форма предлагает удалить или исправить — состояние всегда видимо, молчаливых пропусков нет.
- Storage недоступен — сервис не регистрируется в ростере, чип работает со штатными пресетами, кнопка «＋» показывает ошибку вместо формы.
- Конфликт одновременного обновления одной записи — по версии записи (оптимистическая блокировка), проигравший получает ошибку и свежее состояние.

## Безопасность

- Пользовательский ввод — значения типизированной конфигурации плагинов; ни YAML, ни `!!js`, ни файлы пользователя не попадают в Loader. Путь remote → storage → `agentPresets.register()` проходит объектами JS, парсинга пользовательского текста как конфига нет.
- Инструменты остаются под песочницей `workspace-write` с подтверждениями — оверлей это не ослабляет; whitelist не содержит shell/fs/web/jobs.
- Инструкция — model-visible текст; риск промпт-инъекции эквивалентен тому, что пользователь мог бы написать в чат (те же инструменты, та же песочница). Новых дверей не появляется.
- Лимит числа агентов на сайт (конфиг, дефолт 50) — от переполнения ростера и роста prefix'ов.

## Тестирование

- Юнит-тесты сервиса: CRUD, валидация схемы (каждое правило отклонения — негативный кейс), регистрация/ретир ревизий, карантин битой записи, восстановление после рестарта, конфликт версий.
- Web e2e: создание кастомного агента через форму, появление в чипе, выбор и первый ход, рестарт с сохранением, удаление. Базируется на существующем `apps/web/tests/agent-preset-selection.e2e.ts`.
- Снапшоты: выбор кастомного пресета — model/user-output снапшот по политике ключевых поверхностей (событие `agent-preset/selected` уже проецируется).
- Доки: README обоих пакетов (RU/ZH-триплеты), обновление `packages/bundle/web-app/README.md` при необходимости; `doc-sync`; сборка `build` перед завершением.

## Ограничения и отложенное

- Список общий на сайт: без identity нет «мои агенты vs чужие»; правка и удаление доступны всем вошедшим. Identity/ACL — отдельная задача.
- Ростер в открытом окне не пушится чужими изменениями: чужой новый агент появляется после перечитки (перезагрузка страницы, reconnect — штатный refresh по `connection/reset`). Для объёма сайта это приемлемо; живой пуш — с identity-этапом.
- Whitelist не включает delegation, schedule, skills и прочие составные плагины — расширение осознанное и делается конфигом оверлея, не кодом.
- Инструкции кастомных агентов не ревьюятся — модерация контента вне объёма; оскорбительный текст виден всем пользователям сайта в списке.
- Вариант C (Creator на клиенте) остаётся отклонённым, пока нет изоляции процесса на пользователя; возвращение к нему — отдельный дизайн.
