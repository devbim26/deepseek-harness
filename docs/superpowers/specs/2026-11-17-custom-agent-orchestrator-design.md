# Дизайн: оркестраторы и видимость для кастомных агентов

Дата: 2026-11-17. Статус: на утверждении пользователем.

## Контекст и цель

Кастомные агенты клиентского прода (`north-waterfront.dev-bim.com`, дизайн 2026-11-15) — это записи `agent-preset-custom`, монтируемые в реестр пресетов как `custom/<slug>`. Сегодня такой агент — только выбор «сверху» в пикере при старте сессии: запустить один агент из другого сайт не умеет, делегирование сознательно исключено из `preset-standard` оверлея.

Штатный механизм для запуска детей уже есть и работает host-plane: `@deepseek-ai/dsh-tool-subagent` с провайдером `spawn` умеет `agentPreset` (пресет ребёнка по умолчанию) и `allowedAgentPresets` — статический список точных id, который модель видит как enum `agent_preset`; пресеты разрешаются в момент запуска ребёнка, отсутствующий id даёт ошибку вызова, а не падение.

Цель — две возможности в модалке создания агентов:

1. Статус «оркестратор»: чекбокс у агента; при включении открывается раздел выбора запускаемых кастомных агентов (чекбоксы). Оркестратор получает инструмент запуска выбранных агентов как субагентов.
2. Чекбокс «видимость в интерфейсе»: управляет появлением агента в пикере пресетов (выборе режима); скрытый агент остаётся запускаемым оркестратором.

## Решения брейншторма

- Подход A — «типизированные швы без изменения движка»: статус и список хранятся в записи агента, синтез монтирует готовую строку `tool-subagent` с `allowedAgentPresets` из записи. Вариант B (wildcard `custom/*` в `tool-subagent` с резолвом по живому реестру) отклонён: теряет посоставной выбор «кого именно запускает этот оркестратор» и меняет поведение всех деплоев. Вариант C (отдельный тип пресета-оркестратор со своей поверхностью) отклонён: вдвое больше механизмов ради того же результата.
- Скрытый агент скрыт только из пикера; оркестратор запускает его как обычно (скрытый = «внутренний рабочий»).
- Оркестратор запускает только обычных агентов: цепочек нет, у подчинённых инструмента делегирования нет.
- Удаление агента — каскад без блокировок: id вычёркивается из списков запуска всех оркестраторов; ос­тавшийся без агентов оркестратор сохраняет флаг, но строка инструмента не монтируется.
- Фича включается витриной деплоя: отдельное поле `delegation` в конфиге `agent-preset-custom` (шаблон строки делегирования: `name` + `config`). Нет поля — нет чекбокса «оркестратор» в форме (форма предлагает только то, что есть в витрине — то же правило, что у чекбоксов инструментов). Поле `delegation` живёт отдельно от `allowedTools`, потому что карта `allowedTools` — источник чекбоксов «Инструментов», а делегирование выбирается флагом, а не чекбоксом инструмента.

## Архитектура: компоненты

### 1. Сервис `@deepseek-ai/dsh-agent-preset-custom`

Расширение закрытой схемы записи (наследует границы remote-валидации):

| Поле | Ограничение |
|---|---|
| `isOrchestrator` | bool, по умолчанию `false`; у существующих записей — `false` |
| `delegates` | id `custom/<slug>`; непустой при `isOrchestrator`; каждый id существует, ссылается на обычного агента (не оркестратора) и не на себя |
| `hidden` | bool, по умолчанию `false` — только видимость в пикере |

Правила записи (`create`/`update`):

- `isOrchestrator && delegates.length === 0` → `custom-agent-presets/invalid`.
- Ссылка на отсутствующий id, на оркестратора или на себя → `invalid`.
- `update`, делающий агента оркестратором, при существующих ссылках на него в чужих `delegates` → `invalid` (инвариант «запускают только обычных»).
- `update` переименовывает/меняет инструкции — id не меняется, ссылки не страдают.

Синтез определения:

- Обычный агент — без изменений: персона, `basePlugins`, выбранные строки витрины.
- Оркестратор с непустым `delegates` — дополнительно строка `{ id: 'delegation', name: config.delegation.name, config: { ...config.delegation.config, allowedAgentPresets: record.delegates } }`. Витрина задаёт `name` и базовый `config` (провайдер, имя инструмента); сервис только подставляет `allowedAgentPresets` — имена плагинов по-прежнему приходят только из оверлея деплоя.
- Оркестратор с опустевшим после каскада `delegates` — строка инструмента не монтируется (флаг сохраняется, ростер помечает «нет агентов»).
- Правка `delegates` — новая ревизия пресета: работающие сессии доживают на старом составе (документированное свойство реестра).

`delete` — каскад: из `delegates` всех записей удаляется id удаляемого; затронутые записи перемонтируются новыми ревизиями.

Policy remote (`list`) дополняется `delegationAvailable: boolean` — витрина несёт поле `delegation`; по нему форма показывает/скрывает чекбокс «оркестратор».

### 2. Реестр пресетов и пикер

- `PresetDefinition` получает необязательный клиентский флаг `hidden?: boolean`; `agent-preset-custom` проставляет его из записи; remote `agentPresets/list` проносит; пикер новой сессии и ростер настроек фильтруют скрытые.
- Из реестра скрытый пресет не исчезает: определение остаётся смонтировым, `allowedAgentPresets` оркестратора резолвится штатно.
- Реестр семантически не меняется — флаг клиентский, серверной валидации не подлежит.

### 3. Модалка `@deepseek-ai/dsh-client-ui-custom-agents`

- Центральная панель полей: чекбокс «Оркестратор» (только при `delegationAvailable`) и чекбокс «Видимость в интерфейсе» (включён по умолчанию).
- Правая панель: под «Инструментами» секция «Запуск агентов» — чекбокс-список остальных обычных агентов; секция неактивна, пока не отмечен «Оркестратор». Сам агент и другие оркестраторы в списке не показываются.
- Ростер слева: бейдж «оркестратор» и пометка скрытого агента.
- Копия — через словари `customAgents` (ru/en/zh), дизайн — по `dsh-client-ui-ux`.

### 4. Оверлей NW

Конфиг `agent-preset-custom` пополняется полем (включает фичу на сайте):

```yaml
delegation:
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent
```

Поле живёт рядом с `allowedTools`, но не в самой карте: `allowedTools` — источник чекбоксов «Инструментов», а делегирование выбирается флагом «оркестратор» и чекбоксом не рендерится. Запись агента не хранит его в `tools` — ссылки на запускаемых агентов лежат в `delegates`. Отдельные host-строки не нужны: реестр subagent'ов и spawn-бэкенд host-plane и уже работают в проде NW.

## Что видит модель

У сессии под пресетом оркестратора: инструмент `subagent` с enum `agent_preset` (id выбранных агентов) и секция delegation guidance. Изменение набора `delegates` меняет схему только для новых сессий/ревизий. У подчинённых инструмента нет — глубина делегирования не превосходит один уровень.

Дополнение 2026-11-18 (после живого теста: модель не знала, кого запускать, выдумывала своих субагентов и не передавала `agent_preset`): поле `delegation.rosterTemplate` в конфиге деплоя — подводка, после которой синтез добавляет в persona оркестратора ростер делегатов (`- <id> «<имя>» — <описание>` на каждого). Ростер — деривация при монтировании: правка делегата перемонтирует ссылающиеся оркестраторы (записи и их версии не меняются), осиротевший id в хранилище — громкая ошибка при монтировании.

## Безопасность

Расширение витрины (поле `delegation`) — осознанное решение деплоя по правилу «raise allowedTools only with a sandbox review»: дети по-прежнему собираются только из строк витрины и `basePlugins`, пользовательский ввод остаётся типизированными значениями. `delegates` ограничены существующими обычными агентами того же сайта; цепочек нет.

## Тесты

- Сервис: CRUD с новыми полями; все ветки `invalid`; каскад удаления; синтез с `allowedAgentPresets` и без (опустевший); legacy-записи без новых полей; policy `delegationAvailable`.
- Реестр/пикер: `hidden` проносится в `agentPresets/list` и фильтруется в ростере.
- Модалка: компонентные тесты — гейтинг чекбокса витриной, неактивная секция, список без себя/оркестраторов, бейджи.
- Снапшот (keyless): записанная сессия под оркестратором — инструмент и enum в ожидаемом выводе.
- SDK не меняются: `SessionEventMap` и цикл не затронуты, новых модельных событий нет.
