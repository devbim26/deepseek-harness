# 发布服务的预置行需要 isolate 域

[English](guide.md) | 中文

## 变更

`@deepseek-ai/dsh-tool-pdf` публикует сервис `pdfReports`, `@deepseek-ai/dsh-tool-present` — сервис `fileDeliveries`, а `@deepseek-ai/dsh-agent-orchestrator` — сервис `agentOrchestrator`. Пресетная строка, монтирующая один из этих пакетов, должна удерживать публикуемый сервис в isolate-реалме. Без него сервис попадает в корневой realm, реестр пресетов отказывается монтировать пресет, и любая сессия, запрашивающая такой пресет, падает с `agent-preset/invalid: Preset services require isolate realms: <имена сервисов>`.

Это касается операторов, чей профиль, патч или оверлей объявляет пресет — строку `@deepseek-ai/dsh-agent-preset` либо кастомного агента, созданного через `@deepseek-ai/dsh-agent-preset-custom`. Строки, монтирующие только инструменты без сервиса, продолжают работать без изменений. Кастомные агенты, созданные через менеджер, синтезируются с уже расставленными реалмами.

## 迁移

1. Дайте каждой пресетной строке, монтирующей один из этих пакетов, карту `isolate` с именем публикуемого сервиса:

   ```yaml
   - id: tool-pdf
     name: '@deepseek-ai/dsh-tool-pdf'
     isolate:
       pdfReports: true
   - id: present
     name: '@deepseek-ai/dsh-tool-present'
     isolate:
       fileDeliveries: true
   ```

   Сервис `agentOrchestrator` пакета `@deepseek-ai/dsh-agent-orchestrator` оформляется так же.

2. Внутри `cordis:group`, который уже объявляет `isolate` для этого сервиса, не задавайте дочерним строкам собственную карту `isolate`. Реалм группы покрывает её детей; ребёнок со своим реалмом публикует сервис под символом, которого не видят остальные строки группы, и движок оркестратора не находит сервис отчётов, которым записать свой PDF.

3. Проверьте миграцию: профиль стартует, а его пресеты появляются в ростере без пометки `broken`; `dsh --profile <профиль> --dump-config` показывает карту `isolate` рядом со строкой; создание сессии проходит успешно.
